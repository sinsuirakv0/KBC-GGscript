# キャラ解放・レベル変更のオフライン統合設計

## 目的

`キャラ解放とレベル変更.lua`が行う保存状態の変更を、`lua/kbc-status-test.lua`へ統合する。実行時にネットワーク通信を行わず、キャラ名・フォーム数は公開済みの`data/unit-index.csv`、ステータスは`data/units/unitNNN.csv`、保存状態はGameGuardianから読み出したメモリだけで扱う。

## 既存スクリプトの依存関係

元スクリプトには次の外部依存がある。

| 依存先 | 現在の用途 | オフライン統合後 |
| --- | --- | --- |
| 外部ローダーの`req`・`exe` | Luaをダウンロード・実行 | 使用しない |
| `funcs/setup.lua` | `base`アドレスの探索 | 必要な探索ロジックだけをローカルLuaへ移植 |
| `funcs/library.lua` | 暗号化・検索補助関数 | 現在の解放・レベル変更本体では直接使用していないため使用しない |
| battlecats-dbのキャラ一覧 | 名前・カテゴリ・IDの対応 | `data/unit-index.csv` |
| battlecats-dbの最終形態表 | フォーム上限 | `unit-index.csv`の有効フォーム行 |

元スクリプトの`base`は保存領域の基準を探すための値であり、ユニット静的ステータステーブルの基準とは別である。現在のステータス変更側が持つ`unitTableAddress`と共有してはならない。

## ローカルデータとID対応

`unit-index.csv`の`unit_id`は0始まりである。一方、元スクリプトが保存領域の配列へ使うキャラ番号は1始まりである。

```text
unit_id = 0             # ネコ
save_id = unit_id + 1   # 保存配列でのネコ
```

この変換を`saveId = character.id + 1`へ集約する。外部サイトの3桁ID文字列を経由しない。

## 保存状態の3配列

元スクリプトのメモリ探索結果`char`は、次の3配列として扱う。

| 配列 | 添字 | 用途 | 元スクリプトの操作 |
| --- | ---: | --- | --- |
| `ownership` | `save_id` | キャラ所持・解放状態 | ネコの所持値を対象へコピー |
| `level` | `save_id * 2 - 1`、`save_id * 2` | レベルとプラス値の2 DWORD | エンコード済みの値を書き込む |
| `form` | `save_id` | 保存上の選択フォーム | 0始まりフォーム番号を書き込む |

統合側では`state.saveCharacterTables`に各レコードのアドレスを保持する。探索は最初の保存操作時だけ実行し、同じLua実行中は再利用する。

## アドレス解決

### 1. 保存基準アドレス

外部`setup.lua`が使う時差値パターン探索をローカル実装へ移す。32-bitでは元スクリプトと同じ複合範囲`48`を使う。ネットワークは不要で、使用するのは`gg.getRangesList`、`gg.setRanges`、`gg.searchNumber`だけである。

### 2. 3配列の検出と検証

元スクリプトの数値パターン探索を`resolveSaveCharacterTables()`へ分離する。大量結果は6000件ずつ処理し、候補の再検索は最大8件で終了する。見つけた候補を採用する前に、少なくとも次を確認する。

- 所持・レベル・フォームの3ブロックが期待した順序で並ぶこと
- 対象キャラについて所持1件、レベル2件、保存フォーム1件の実レコードを取得できること
- 対象`save_id`とネコ（`save_id = 1`）の実レコードが存在すること

検証に失敗した候補へは書き込まない。候補上限へ達した場合も検索を繰り返さず、明示的に「保存状態テーブルを確認できない」と表示する。

## 操作ごとの仕様

### キャラ解放

対象は`ownership[save_id]`である。基準となるネコの所持値`ownership[1].value`をコピーする。既存値の削除・一括解放は初期実装へ含めず、対象キャラ1体の解放だけを扱う。

### レベル・プラス値変更

入力は`レベル`と`プラス値`を分ける。元スクリプトのエンコードは次の通りである。

```text
encoded = (level - 1) * 0x10000 + plus
odd256  = floor(encoded / 0x100) % 2 == 1

level[save_id * 2 - 1] = encoded + (odd256 ? 0x200 : 0x100)
level[save_id * 2]     = odd256 ? 0x20000 : 0x10000
```

`level >= 1`と整数値を検証する。現在値の復号表示は、上記の2 DWORDを読み戻してから実装する。元スクリプトにある「フォーム番号から特殊レベルを作る式」は目的・境界条件が未検証のため移植しない。

### 保存上のフォーム変更

ステータス変更で選ぶフォームと、セーブに保存される選択フォームは別の概念である。後者を実装する場合は`form[save_id]`へ0始まりフォーム番号を書き込む。`unit-index.csv`から組み立てる`character.forms`の最大indexを上限にするため、battlecats-dbの最終形態表は不要である。

## UIへの統合

既存のキャラ・フォーム選択の後の操作メニューを次の構成にする。

1. キャラ解放/レベル変更
2. ステータス変更
3. リストに保存
4. 戻る

「キャラ解放/レベル変更」のサブメニューには「キャラ解放」「レベル変更」「戻る」を表示する。レベル変更とキャラ解放は選択フォームに依存しないが、現在の導線を保つため同じ操作メニューに置く。フォーム変更を追加する場合は、ステータス編集用フォーム選択と誤認しないよう「保存フォーム変更」と明示する。

## GG保存リストと凍結

`gg.addListItems`はGGの保存リストへ項目を追加する。GG側でリストをファイルへ保存できるが、アプリのセーブファイルへ直接書き込む機能ではない。

レベル変更はレベル、プラス値、凍結を同じ入力画面へ表示する。凍結チェックボックスは初期状態をオンにする。変更前に同じ2 DWORDの既存リスト登録を解除し、値を書き込んだ後、凍結がオンの場合だけGGの保存リストへ再登録する。

## 実装順序

1. ローカルの保存基準・3配列探索と書き込み前検証を実装する。
2. キャラ1体の解放を実装する。
3. レベル・プラス値の入力、エンコード、現在値表示、凍結を実装する。
4. 必要なら保存フォーム変更を追加する。
5. v15.5.1実機でネコ・タンクネコなど既知キャラを使い、再起動後の反映も別途検証する。
